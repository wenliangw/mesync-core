# 未决设计

> 两份「讨论过、但没定」的东西。放在这里是为了不重复推导——**不是待办，也不含解法**。
>
> 为什么不写解法：写了就会被当成结论读。这个项目本身就在犯「每次重新推导」的病，而这两份讨论正是它的一部分。

---

## 一、记忆事实不单一（同一件事落在多处）

### 症状

Agent 干活时会写记录，但只负责写、不负责对齐。同一件甚至相近的事，会在多处留下决策记录、品味记录，各自演化后互相矛盾。表现为每次做同类决定都在两个答案之间摇摆，而且它没法知道哪个对。

### 病因（已逐条坐实）

| 病因 | 证据 |
|---|---|
| **写入没有「改」的路径** | `src/memory.ts` 的 `slugFor()`：同名文件已存在时主动加 `-2`、`-3`。同一件事写三次 = 三个文件 |
| **检索只在动手前一次** | `templates/mesync-use.md` 的 M1 才 `memory_search`。到 M4 真要写时不再查，而 M1 时它还不知道这次会留下什么 |
| **检索是字面匹配** | `src/search.ts` 用 `includes`。「尺寸」查不到「size」，「UI 库」查不到「组件库」 |
| **措辞在授权重复** | `templates/chain-judge.md` 第 4 行：「一次走链产出一条记忆；同一件事可以走多次」 |
| **两层作用域没有优先级** | 场景级「用 pnpm」与项目级「用 npm」都合法，检索都返回，没有「谁赢」 |
| **否定后不标废** | M3 说「否定 → 重走出错点 → 重建下游」，但旧记录不删也不标作废。下次 M1 又把它和新的并列捞回来 |

### 旧版的病根已拆，但免疫力未生

0.1.0 的心法里有两条**主动要求双写**的指令：

- 总纲：「三者不互斥，各记各的，不要因为『已经记了决策』就跳过品味」
- `_sync_taste.skill.md`：「记录决策时，若决策体现了用户偏好，在决策的 `taste_signals` 字段带上，**并配套落到 `tastes/`**」

新版 templates 里这两句已经不存在（`互斥 / 各记各 / 不要因为` 一处都不剩）。但拆掉病根 ≠ 长出免疫力——上面六条通路一条没少。

### 为什么试过的方案不行

曾提出三条：A（按 kind 决定「改」还是「追加」）、B（M4 加必答问题「已经有一条记录了吗」）、C（一条判断一条主记录，跨块用指针不复述）。

**它们的共同前提是「Agent 知道自己已经有一条了」，而没有任何一条负责让它真的知道。** 剩下六个漏洞：

| 漏洞 | 为什么堵不住 |
|---|---|
| kind 误判 | 同一种情况两次可能落到不同块（一次判 D、一次判 TL），Q0 只查当前 kind，看不见对方 |
| scope 分裂 | 这次判场景级、下次判项目级，Q0 只列当前 scope |
| 标题当地址 | 「组件版本」与「UI 库版本固定」是同一件事，看标题认不出 |
| 清单膨胀 | 某 kind 有 50 条时，同 kind 清单就是 50 行，Agent 会 skim 后写新的。**记录越多，防重越弱**——机制随使用退化 |
| 同一事实的细分 | 「用 pnpm」与「CI 缓存用 pnpm」是同一件事的两层，没有判据说该合并 |
| 时序 | 一个大任务两轮各写一条，第二轮认为第一条「还没验证」 |

补充的两条也只能做到有限的事：**F（同名即撞车，拒绝写入并回显已有内容）**能保证「完全相同」结构上不存在；**G（topic 聚合）+ E（status: superseded）**能让语义重复必须露头、并让裁决有落点。但堵不死「不同 topic、不同 kind、不同 scope，说的却是同一件事」。

### 硬边界

**「语义上是不是同一件事」没有形式判据。** 只要判断权在 Agent，就一定会有漏。差别只在于：漏掉时是安静地多一条，还是能被看见。

## 二、联想心法（用结构相似的经验去试探新任务）

### 想解决什么

人做没做过的事时，会想起性质类似的经验，拿它的做法先试，以评估可行性。现在这套只有「检索」（这条经验在不在）和「工具清单」（有没有现成手段），没有「这件事像不像做过的事」。所以行为是固定的，遇到新情况只能从零推导或问用户。

和检索的分界：

| | 检索 | 联想 |
|---|---|---|
| 问的是 | 这条经验在不在 | 这件事像不像做过的事 |
| 匹配依据 | 字面关键词 | 情形的结构 |
| 产出 | 记录本身 | 一个假设 |
| 确定度 | `!` | `?` |

### 三条挡点（任一条都足以否决）

| 挡点 | 说明 |
|---|---|
| **没有燃料** | 联想两端都要「情形」，而五块记忆存的是结论。能联想起来的只有决策，因为它的正文碰巧写了情形；「不要用 yarn」这类没有情形的记录永远联想不起来 |
| **没有强制力** | 它需要一个「值得才联想」的判据，而这条判据本身是软的，只能靠 Agent 自己想起来——而「靠它自己想起来」已被认定为不可靠 |
| **错得安静** | 检索错、工具错会当场暴露；错误类比会走完 M2、通过 M3，然后作为一条 `!` 的决策进库。它直接喂大上面那个病 |

### 若要做，唯一可接受的形状（未采纳）

- 挂在「查不到」出口，不是新节点（与「提问挂在答不出来」同构），顺序是先联想、再问人
- 产出必须是「像在哪里 / **不像在哪里** / 待验证假设」，标 `?`。「不像」是判断能否迁移的唯一依据，不是补齐格式
- 借来的东西必须标出处，否则日后分不清哪条自己验证过、哪条抄来的
- 联想失败的教训进「纠错」——「我以为像，其实不像，差别在 X」是最高价值的纠错

之所以列出来，是因为下次重启讨论时，这些约束不该被重新推导一遍。**它们是约束，不是方案。**

### 前置条件

联想的天花板 = 记忆里情形信息的多少。**它缺的不是流程，是「情形」这种材料。**

---

## 两个问题收敛到同一点

多事实问题缺「同一件事的稳定标识」，联想缺「这件事是个什么情形」。两者指向同一个东西：

> **记录里没有「情形」。**

只有结论没有情形，于是：同类的事认不出来（重复），相似的事类比不出来（联想）。

而情形本来也该有——项目自己的原则里写着：**泛化不是存一个抽象节点，而是把同一条记忆的 `when` 写得更一般**。情形就是那个 `when`。

---

## 什么条件下重启讨论

观察，不是设想。以下任一条出现，说明该回来了：

**多事实**

1. 真实出现「两条记录说的是同一件事」，且能给出各自的相对路径（不是假想的例子）
2. 同一个问题隔一段时间再问，两次检索给出的答案互相矛盾——说明矛盾已经进到决策里
3. 某个 kind 的记录多到检索输出开始难以通读（阈值等观察到再定，现在定就是拍脑袋）

**联想**

1. 记录普遍带上「情形」，且是自然长出来的（不是为了联想硬塞的字段）
2. 观察到 Agent 主动翻出过结构相似的旧经验——**哪怕结论用错了**。说明能力在，缺的是写法

**反向判据（同样重要）**

- 长期使用后重复稀少 → 心法侧的「宁可少记」「想不清就不记」已经够用，不必加机制
- 从未观察到 Agent 做过自发联想 → 缺的是材料不是流程，别去写心法

反向判据的作用是让这两份讨论**可以被证伪**，而不是永远挂着待办。
