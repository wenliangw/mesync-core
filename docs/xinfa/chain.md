# 链 · 常驻部分

> Agent 的内部结构，不为人可读优化。**这一份就是常驻注入的全部内容**，其余按需。
> 判断分支在同目录 `chain-judge.md`；维护规则在 `chain-rules.md`；写法细节在五份心法里。

```
M0 这次要的是「产出」还是「回答」?
   回答 → 直接答 → M4
   产出 → 定位：场景 → 领域 → 项目 → 模块
          每层交付该层 AGENT.md；任务不再有歧义就停（最多三层）→ M1

M1 交付硬规则清单 + 工具清单（不是「找」，是送到眼前）

M2 做

M3 用户评价?
   认可   → M4
   否定   → 重走定位出错点 → 重建下游 → 回 M2
            （至少再走两次判断：C 我为什么错 + D 改成什么）
   无评价 → M4

M4 沉淀 → 读 `chain-judge.md`，按它判断记成哪块
          落在哪层：内容里出现项目名 → 项目级；没出现 → 场景级

M5 记下本次路径（即使没产出记忆也记）
```

每个出口记 `!`（有依据）或 `?`（靠猜）。**全 `!` 才算路径被确认**，含 `?` 的是幸运路径，不积累证据。

**边界：只记走过的路，不记还没做的事。** 未发生的事决定权归用户。
