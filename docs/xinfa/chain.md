# 链 · 常驻部分

> Agent 的内部结构，不为人类可读性优化。
> **正文只有一处：`templates/mesync-use.md`（约 685 字符）。** 这一份不复制它——同一个形状写两遍，改一处忘一处就会漂移。
> 判断分支在同目录 `chain-judge.md`（M4 才读）；维护规则在 `chain-rules.md`（修链才读）；写法细节在 `meta/` 五份（定下哪一块才读）。

## 它解决什么

省 token 的关键不在「链」这种形式，而在**只常驻必须常驻的**这个决定。链能整条常驻，是因为它放弃了人类可读性：不加解释、不加例子、不排版，压成二十来行。一旦要求「人能读」，它就得膨胀十倍以上，只能按需加载——于是又回到鸡生蛋：不知道要判断，就不会想起去读判断结构。

代价是链出错时人看不见，所以**可以牺牲可读性，不能牺牲可追溯性**（见 `chain-rules.md`）。

## 每个节点为什么存在

| 节点 | 存在理由 |
|---|---|
| M0 二分支（产出 / 回答） | 少了「回答」出口，纯问答轮判不出场景，Agent 只能自己决定要不要走链——那就回到「依赖它自己识别」 |
| M1 交付（不是「找」） | 材料送到眼前才算走完。只嘱咐「记得找」等于没做，因为想不起来的时候正是最需要它的时候 |
| M2 做 | 不解释 |
| M3 三分支（认可 / 否定 / 无评价） | 「无评价」必须显式——否则 Agent 会把没被否定的东西当成被认可的 |
| M4 出口判断 | 见下 |
| M5 路径 | 唯一记录「判断怎么走的」的地方；确定度标记也只活在这里 |

## M1 交付什么

**该层的 `AGENT.md`，一份。** 它同时装三样东西：

- 这个作用域**怎么做**（开工步骤、产物形态、默认做法）
- 这个作用域**必须遵守什么**（违反后果不可逆的那些）
- 这个作用域**已有什么工具**（一行一个，指向说明）

**为什么不拆成 `rules.md` + 工具清单**：拆开之后，同一件事会在场景层和项目层各存一份，最多 4 处各自长大，而每一处都在交付路径上。合并成一份，「该写到哪」就没有歧义了。

**为什么不交付记录**：记录的数量不可控，而检索质量随条数下降。**不能把「被用上」寄托在检索上**——该被交付的东西，不能放进需要命中才能被看见的地方。

## 交付文件有参考线，没有上限

交付文件每任务必到，所以它有参考线（约 2000 字符）。超了工具**仍然写入成功**，只追加一段提醒：按长度列出最长的三块，给三个自问（有两条在说同一件事吗 / 最长那条能不能一句话说完 / 有没有一条该变成检查或注释）。

**它是铃，不是闸门。**

理由：闸门是用机制替 Agent 做判断，而「该不该压缩」是判断。铃只负责察觉，每次越线都响，并且给出具体对象——抽象的数字会被忽略，具体的「这三块最长」不会。允许不整理，下次再超线还会问一次。

超限的真实后果不是被拒，而是**每轮注入变胖**——因为这份文件每任务必到。

## M4 的位置

M4 不是「沉淀」而是「留下什么」，第一问是**它有没有确定的读取路径**，不是「它属于哪一块」。分类在出口之后（详见 `chain-judge.md`）。

## 边界

- **只记走过的路，不记还没做的事。** 指向未来的（承诺、待办、还没定）决定权归用户，不归记忆。
- **一次只处理一件事。** 同一件事变了，就改写原来那条，不要新开一条。
