# 链 · 判断分支（M4 交付）

> 走到 M4 才读这一份。它只回答一个问题：**这次留下的东西该放到哪里。**
> 正文见 `templates/chain-judge.md`；这里说明它为什么长成这样。
> 先定出口，再定记成哪一块。**没有出口的，不记。**

## 一、出口判据

```
Q1 它指向未来?（承诺 / 待办 / 还没定）        y→不记（归调度）              n→Q2
Q2 机器能替你检查吗?（错了会当场报错那种）    y→写成检查：lint/测试/hook    n→Q3
Q3 该生效的地方已经有了吗?
   （代码注释 / commit / 项目文档里已经写着）  y→不记（那是重复）            n→Q4
Q4 这一层每任务都要照做或知道吗?             y→doc_write 进该层 AGENT.md   n→Q5
Q5 需要时能靠已知关键词找到它吗?             y→记成五块之一                n→不记
```

### 为什么是这个顺序

三条读取路径的可靠度是递减的：

| 路径 | 可靠度 | 为什么 |
|---|---|---|
| 机器检查（lint / 测试 / hook） | 最高 | 不会忘记，不依赖 Agent 想起来 |
| 项目里就地（注释 / commit / 配置） | 高 | 改到那儿一定会看见 |
| 交付文件（`AGENT.md`） | 高 | 每任务必到 |
| **记录（`records/`）** | **最低** | **只在被追问原因时才读** |

**记录是这五种归宿里最不可靠的一种，所以它不该是默认选项。**

这条顺序还有一个直接后果：**大部分东西的正确答案是「不记」。** 这不是保守，是把「记了但用不上」换成「不记但用得上」。

### Q5 是认真的

「已知关键词」不是形式要求：记之前先想，将来会用什么词找它。**想不出词，就说明它进不了任何读取路径**——那它就是一条死记录。

这也是为什么 `memory_search` 只做**查找**（我知道有这么一条、忘了细节），不承担召回（我不知道有什么、你帮我找）。数量不可控时，召回不可靠。

## 二、五个叶子

Q5 为 y 才用。叶子不是分类标签，是**交付点**——走到叶子必然拿到那份写法，所以「该看哪份心法」不需要判断。

| 叶子 | 交付 | 写什么 |
|---|---|---|
| K 认知 | `meta/cognition.md` | 结构与约束 / 怎么验证还成立 / 来源 |
| D 决策 | `meta/decision.md` | 定了什么 / 为什么（取舍·判定·外部约束）/ 何时该重考虑 |
| T 品味 | `meta/taste.md` | 对象 / 方向 / 理由 / 边界 / 产物指针 |
| C 纠错 | `meta/correction.md` | 症状 / 触发 / 检查（动作）/ 止损 |
| TL 工具 | `meta/tool.md` | 做什么 / 何时用 / 怎么调 / 会改什么 / 结果怎么看 |

怎么在叶子之间分：

```
来自用户对某个产物的评价?  认可→T
                          否定→用户事先说过这个要求吗?
                                说过  → C（判断失误，我该知道）
                                没说过→ 不是纠错，是缺信息 → K
它本身是个可直接执行的动作? 有现成工具 → 直接用它，不要记
                          没有但输入输出能说清 → TL
要推翻它得先知道为什么?    y→D    n→K
```

## 三、else 出口是链的缺口，不是容错

任何节点答不出来就掉到散文心法，并记一句「我凭什么这么判」。

**掉落的记录就是链生长的原料**——同一个点掉两次，才允许给它加分支。一次不构成理由。

## 四、否定不等于「我错了」

用户否定一个产物，有两种完全不同的原因：

| 原因 | 该记什么 | 例子 |
|---|---|---|
| **信息缺失**：用户事先没说过这个要求 | 认知 + 该层 `AGENT.md`（确立默认值） | 「第一次没说用 3.2，我用了 3.1」 |
| **判断失误**：依据本来就有，我没用好 | 纠错 | 「项目里明明写着 3.2，我读了却用 3.1」 |

判据一句话：**用户事先说过吗？**

分不清的后果很实际：把「需求没说清」全记成「我判断错了」，纠错块会被灌满，最后它的诊断价值就没了。

## 五、落在哪一层

```
内容里出现具体项目名 → scope=project（只对这个项目）
内容里不出现项目名   → scope=scenario（所有项目通用）
```

「以后所有项目都用 pnpm」→ 场景级；「A 项目的测试要带 --filter」→ 项目级。没有场景级这个落点，前一类话就没有地方存——它不属于任何一个项目。

## 六、一次判断只落一条

「一次走链产出一条记忆；同一件事可以走多次」这句话已经被删掉——它是一条**授权重复**的措辞。

改成：**一次只处理一件事；同一件事变了，就改写原来那条，不要新开一条。**

一条否定确实可能同时涉及多块（「这个配色不好，我不喜欢冷的」= 品味 + 纠错 + 决策）。处理办法不是拆成三条同时写，而是**按出口优先级选一条**，其余留在路径里（`path_record`），下次同类情形再落。
