# 链 · 判断分支（M4 交付）

> 走到 M4 才读这一份。它只回答一个问题：**这次留下的东西，记成哪一块。**
> 一次走链产出一条记忆；同一件事可以走多次。叶子后面的路径是写法细节。

## 入口

```
Q1  这条经验指向未来?（承诺 / 待办 / 还没定）   y→不记（归调度）              n→Q2
Q2  它来自用户对某个产物的评价?                认可→T    否定→C（并再走一次 D）  n→Q3
Q3  它是个可重复执行的动作?                    y→Q3a     n→Q4
Q3a 已有现成工具?                            y→读说明·用它                  n→Q3b
Q3b 输入输出能说清且无「看情况」?              y→TL      n→Q4
Q4  要推翻它，需先知道为什么这么定?            y→D       n→K
```

> Q3 问的是**这条经验本身是不是一个动作**，不是「我刚才有没有动手」——走到 M4 时手已经动过了。

**任何 `else` 出口 → 退回散文心法自己判断**，并把「我凭什么这么判」记一句作为掉落证据。

## K · 认知（写 → `meta/cognition.md`）

```
K1 说得清怎么验证它还成立吗?               n→不记（那是猜测）
K2 违反后果不可逆?                        y→标 hard（进常驻清单）
K3 写结构与约束，不抄代码
K4 可复验→写验证方式 | 只能人确认→写来源 | 观察→写时间与样本
```

## D · 决策（写 → `meta/decision.md`）

```
D1  原因类型?          取舍→D1a  判定→D1b  外部约束→D1c  else→散文
D1a 写被放弃的方案 + 为什么不用
D1b 写违反了哪条 + 怎么防
D1c 老实写「没得选」，不要编放弃项
D2  写不出原因?                           y→退回 Q4（它不是决策）
D3  写「什么情况下该重新考虑」（比放弃项更耐用）
D4  会反复执行且不需再解释?                y→挂硬规则
D5  改主意?                              y→追加新决策 + 指向旧的；不改旧正文
```

## T · 品味（写 → `meta/taste.md`）

```
T1 会改变我下次的默认做法吗?               n→不记（那是任务约束）
T2 结论还是倾向?   结论→写 对象/方向/理由/边界
                   倾向→写 方向 + 反例边界（否则会被过度泛化）
T3 边界是谁定的?   用户→标「用户说的」  我推的→标「推断·待确认」
T4 留产物指针：提交号 > 文件路径 > 描述（打不开的指针等于没留）
T5 长出了硬规则?                          y→先怀疑它其实是决策
```

## C · 纠错（写 → `meta/correction.md`）

```
C1 换个情况还会再犯同一个判断错误吗?        n→不记
C2 我错在哪类?   没看就动手 / 看错了 / 该问没问 / 知道但没做
C3 「知道但没做」?                        y→记下来没用，必须变工具或硬规则
C4 四段：症状 / 触发 / 检查 / 止损；检查项必须是动作
C5 写不出检查项?                          y→先别记，还没想明白
```

## TL · 工具（写 → `meta/tool.md`）

```
TL1 已有现成的?                           y→先找再造：读说明再用
TL2 输入输出能说清且无「看情况」?           n→别造（判断还没稳定）
TL3 只做一次?                             y→别造
TL4 说明六项：做什么 / 何时用何时不用 / 怎么调 / 会改什么 / 怎么看结果 / 失败怎么办
TL5 「会改什么」必须写明（副作用）
TL6 报告实际做了什么，不只退出码（静默成功最坏）
TL7 报错或结果不对?                       y→修，不绕过（绕过三次，工具就死了）
```
