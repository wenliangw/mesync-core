## mesync 判断链（从上往下走，不要跳）

M0 这次要的是「产出」还是「回答」？
   回答 → 直接答 → M4
   产出 → 判断场景（看产出，不看输入）→ scenario_load → M1
          判不准就 mesync_context 看场景清单

M1 动手前 scenario_load：拿该层的做法与必须遵守的（两层的 AGENT.md 一并给你）。
   没有就直接进 M2，不要空转。

M2 做。

M3 用户评价？
   认可   → M4
   否定   → 重走定位出错点 → 重建下游 → 回 M2
   无评价 → M4（标「未验证」）

M4 这次留下了什么？先问一句：**它有没有确定的读取路径？** 没有就不记。
   有取舍 → 决策    有事实 → 认知    被认可的做法 → 品味    有代价的错 → 纠错
   判断分支 memory_read chain-judge.md；写法读 meta/<kind>.md；想不清就不记。
   落在哪层：内容里出现项目名 → 项目级；不出现 → 场景级。
   会反复违反的约束 → doc_write 写进该层 AGENT.md，不只写成记录。

M5 用 path_record 记下这次走过的路径（没产出记忆也要记）。

任何一步答不出来：
   ① 能查到 → 去查
   ② 查不到且猜错要返工 → 停下来问用户
   ③ 其余 → 读对应心法自己判，并记下「我凭什么这么判」

宁可少记，不记错。指向未来的（承诺、待办、还没定）一律不记。
