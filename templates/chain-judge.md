# 判断链：这条东西的出口在哪

> 走到 M4 才读这一份。它只回答一个问题：**这次留下的东西该放到哪里。**
> 先定出口，再定记成哪一块。**没有出口的，不记。**
> 一次只处理一件事；同一件事变了，就改写原来那条，不要新开一条。

## 一、出口（先问，决定放哪）

```
Q1 它指向未来?（承诺 / 待办 / 还没定）        y→不记（归调度，不归记忆）      n→Q2
Q2 机器能替你检查吗?（错了会当场报错那种）    y→写成检查：lint / 测试 / hook  n→Q3
Q3 该生效的地方已经有了吗?
   （代码注释 / commit / 项目文档里已经写着）  y→不记（那是重复，不是记忆）    n→Q4
Q4 这一层每任务都要照做或知道吗?             y→doc_write 进该层 AGENT.md     n→Q5
Q5 需要时能靠已知关键词找到它吗?             y→记成下面五块之一              n→不记
```

为什么 Q2、Q3 排在最前：**机器检查不会忘记，项目里就地的东西一定会被读到**；而记录只在被追问原因时才读。三条路的可靠度递减，能用前面的就别用后面。

Q5 的「已知关键词」是认真的：记之前先想，将来你会用什么词找它。想不出词，就说明它进不了任何读取路径。

## 二、记成哪一块（Q5 为 y 时才用）

```
K  认知  事实与约束        → meta/cognition.md
D  决策  为什么这么定      → meta/decision.md
T  品味  被认可的判断      → meta/taste.md
C  纠错  有代价的错        → meta/correction.md
TL 工具  可直接执行的动作  → meta/tool.md
```

怎么分：

```
来自用户对某个产物的评价?  认可→T
                          否定→再问：用户事先说过这个要求吗?
                                说过  → C（判断失误，我该知道）
                                没说过→ 不是纠错，是缺信息 → K
它本身是个可直接执行的动作? 有现成工具→直接用它，不要记
                          没有但输入输出能说清→TL
要推翻它得先知道为什么?    y→D    n→K
```

## 三、用哪个工具写

```
记录（五块）  → memory_write(kind, title, content, scope)
该层交付文档  → doc_write(path, content)
临时答案      → memory_write(kind: "pending")
                升格：产物被认可 → 按五块写正式记录 → memory_discard 删掉临时
                丢弃：被否定 → memory_discard 直接删，不留痕
走过的路径    → path_record(line)
```

**数据根可能不在你自己的文件工具能到达的范围**，一律走这几个工具，不要自己找路径写。

## 四、落在哪一层

```
内容里出现具体项目名 → scope=project（只对这个项目）
内容里不出现项目名   → scope=scenario（所有项目通用）
```

例：「以后所有项目都用 pnpm」→ 场景级；「A 项目的测试要带 --filter」→ 项目级。

## 五、AGENT.md 有参考线，没有上限

交付文件是每任务都送到的，所以它有参考线（约 2000 字符）。超了工具会提醒你重新整理，**但不拦你写**——判断归你：

- 有两条其实在说同一件事吗？
- 最长那条能不能一句话说完？
- 有没有一条其实该变成检查，或者写进代码注释？

想完觉得已经最简，就放着。**允许不整理，但每次超线都会再问一次。**

写一条硬约束时，带上来路：

```
- 出稿前 grep 一遍 import，确认组件库版本是 v3.2
  来源：scenarios/design/records/decision/组件版本.md
```

「来源」不能省：规则是「做什么」，来源是「为什么」。规则被质疑时要能追回去。

## 六、任何节点答不出来

**任何 `else` 出口 → 退回散文心法自己判断**，并把「我凭什么这么判」记一句。

这句掉落记录是链生长的原料：**同一个点掉两次，才允许给它加分支。**
