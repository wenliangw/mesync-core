## 纠错：有代价的错，和怎么不再犯

纠错记的是**我判断错了，而且付出了代价**。

只有代价还不够，还要能说清下次怎么防。写不出检查项的，先别记——那说明还没想明白。

### 第一个问题：换个情况还会再犯吗

不会 → **不记**。一次性的手滑不值得占一条记忆。

会 → 继续。

这一条是关键：纠错的价值在**可迁移**。只对这一次成立的错误，记下来只会误导下次。

### 我错在哪一类

四类，判错类别的价值在于它对应不同的防线：

| 类别 | 特征 | 对应的防线 |
|---|---|---|
| **没看就动手** | 有信息，没去读 | 动手前先查 |
| **看错了** | 读了，理解偏了 | 引用原文，别凭印象 |
| **该问没问** | 信息不在手边，也没问 | 停下来问用户 |
| **知道但没做** | 明明知道该怎么做，还是没做 | **这条最严重**（见下） |

### 「知道但没做」：记下来没用

前三种记成纠错就够了。第四种不行——它不是知识缺口，是执行力缺口。

**这种错必须变成工具或者硬规则，不能只留一条记录。**

理由很直接：知道却做不到的事，再写一遍还是做不到。只有把它变成「机器执行」或者「看到就遵守」，才真的挡住了。

### 四段必须写全

1. **症状**——当时看到什么现象（越具体越好，这是将来认出来的唯一线索）
2. **触发**——什么情况下会发生（这是检查它的时机）
3. **检查**——**具体的动作**，不是「注意一下」
4. **止损**——已经发生了怎么办

第三段是全部价值所在：

```
❌ 检查：下次注意版本号
✅ 检查：生成稿子前 grep 一遍 import，确认组件库版本是 v3.2
```

**检查项必须是动作。** 「注意」「小心」「留意」都不是动作，它们不可执行，所以永远不会被执行。

### 同一个错第二次出现

说明这条纠错**没用**。

不要再加一条更好的纠错——升级它的形态：

- 变成硬规则（写进同层 `rules.md`，进 M1 交付）
- 或者变成工具（机器执行，不依赖记性）

一条纠错被犯第二次，就是在告诉你「这一层太软了」。

### 可以删吗

不建议删。写清「这条已经被某条硬规则覆盖」，比删掉它更有用——它解释了那条规则为什么要存在。
